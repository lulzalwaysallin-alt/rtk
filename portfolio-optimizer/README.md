# 포트폴리오 최적화 분석기

한국·미국 주식을 대상으로 **마코위츠 평균-분산 최적화**를 수행하는 웹 대시보드입니다.
비개발자가 브라우저에서 클릭만으로 쓸 수 있도록 만들었습니다.

> **사용자용 안내서는 [사용설명서.md](사용설명서.md) 를 보세요.**
> 비개발자에게 전달할 인쇄용 자료는 [docs/포트폴리오_최적화_분석기_안내.pdf](docs/포트폴리오_최적화_분석기_안내.pdf) 입니다.
> 이 문서는 설치·구조·개발을 다룹니다.

## 무엇을 하나

| 기능 | 설명 |
|---|---|
| 최적 비중 계산 | 최대 샤프 / 최소 변동성 / 위험균등 / 목표수익률 4가지 전략 |
| 효율적 투자선 | 같은 위험에서 얻을 수 있는 최고 수익 곡선과 현재 조합의 위치 |
| 백테스트 | 리밸런싱·거래비용을 반영한 과거 성과, 지수 대비 비교 |
| 워크포워드 검증 | 매 시점 과거 데이터만으로 재최적화 — 미래 정보 없이 검증 |
| 위험 분해 | 종목별 위험기여도, 상관관계 히트맵, 최대낙폭 |
| 실매수 계획 | 투자금액을 넣으면 종목별 매수 주식 수까지 계산 |
| 엑셀 내보내기 | 모든 표와 원본 시세를 시트별로 정리한 xlsx |

## 출처

두 공개 저장소를 참고했습니다.

- [hyunyulhenry/quant_py](https://github.com/hyunyulhenry/quant_py) — 『파이썬을 이용한 퀀트 투자
  포트폴리오 만들기』. 14장(포트폴리오 구성), 16장(백테스팅)의 접근을 따랐습니다.
- [TwinKay/Portfolio_Optimization_Analyzer](https://github.com/TwinKay/Portfolio_Optimization_Analyzer)
  — 샤프지수 기반 최적 비중 추천이라는 문제 정의와 화면 구성을 참고했습니다.

원본과 달라진 점:

- **PyQt5 → Streamlit.** 원본은 Windows 32비트 파이썬 + 키움 OpenAPI COM 이 필요해
  설치 장벽이 높습니다. 웹 대시보드로 바꿔 OS를 가리지 않게 했습니다.
- **증권사 API 제거.** 데이터는 FinanceDataReader/yfinance 공개 시세로 받고,
  주문 기능은 넣지 않았습니다. 계좌 인증이 필요 없고 오작동으로 인한 손실 위험도 없습니다.
- **워크포워드 검증 추가.** 최적화 구간과 검증 구간이 같으면 성과가 과대평가됩니다.
  미래 정보를 배제한 검증을 나란히 보여줍니다.
- **최적화기 직접 구현.** `riskfolio-lib` 대신 `scipy.optimize` 로 구현해 의존성을 줄이고,
  해석적으로 정답을 아는 입력으로 정확도를 검증했습니다.

## 설치와 실행

가장 쉬운 방법은 `실행하기.bat`(Windows) 또는 `실행하기.sh`(macOS/Linux) 더블클릭입니다.
가상환경 생성부터 패키지 설치, 브라우저 실행까지 알아서 합니다.

직접 하시려면:

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

`http://localhost:8501` 이 열립니다.

### 사내 서버에 올리기

여러 명이 쓸 경우 서버에서 한 번만 띄우고 URL을 공유하면 됩니다.

```bash
streamlit run app.py --server.address 0.0.0.0 --server.port 8501
```

## 구조

```
portfolio-optimizer/
├── app.py                  화면. 위젯 배치와 렌더링만 담당한다
├── src/portfolio/
│   ├── data.py             시세 수집. 유일하게 네트워크를 쓰는 모듈
│   ├── metrics.py          수익률·위험 지표 (샤프, MDD, VaR, 베타 …)
│   ├── optimize.py         마코위츠 최적화와 효율적 투자선
│   ├── backtest.py         리밸런싱 시뮬레이션 (고정비중 / 워크포워드)
│   ├── pipeline.py         분석 오케스트레이션. 화면과 계산의 경계
│   ├── charts.py           Plotly 차트
│   └── report.py           엑셀 내보내기
└── tests/                  pytest. 네트워크 없이 전부 돌아간다
```

의존 방향은 한 방향입니다.
`app.py` → `pipeline` → (`optimize`, `backtest`, `metrics`), `data`, `charts`, `report`.
`pipeline` 아래로는 네트워크 접근이 없어 테스트에서 그대로 호출할 수 있습니다.

### 설계 메모

**데이터 소스 이중화.** 국내는 FinanceDataReader(네이버), 실패 시 yfinance(야후,
`.KS`/`.KQ` 접미사 자동 시도)로 넘어갑니다. 한쪽이 죽어도 앱은 계속 돕니다.

**거래일 교집합.** 한국·미국은 휴장일이 다릅니다. 빈 칸을 직전 값으로 메우면 그날
수익률이 인위적인 0이 되어 변동성과 상관계수가 실제보다 낮게 나옵니다. 그래서 메우지
않고 모든 종목이 실제로 거래된 날만 씁니다.

**위험균등은 로그배리어로.** 위험기여도 제곱오차를 그대로 최소화하면 목적함수가
비볼록이라, 음의 상관을 가진 종목의 비중을 0으로 밀어버리는 구석해에 갇힙니다.
볼록형 `½wᵀΣw − (1/n)Σlog(wᵢ)` 를 풀어 위험기여도가 정확히 균등해지도록 했습니다
(`optimize._risk_parity_weights`).

**공분산 축소.** 종목 수가 관측일 수에 비해 많으면 표본 공분산이 불안정합니다.
기본 10%를 대각행렬 방향으로 축소합니다.

**재현성.** SLSQP는 지역해에 갇힐 수 있어 여러 시작점에서 풀고 최선을 고릅니다.
난수 시드를 고정해 같은 입력이면 항상 같은 비중이 나옵니다.

## 개발

```bash
pip install -r requirements-dev.txt
python -m pytest              # 120개 테스트, 네트워크 불필요
python -m pytest -k optimize  # 일부만
```

테스트 방침:

- **해석적 검증 우선.** 무상관·동일분산 2종목처럼 손으로 답을 낼 수 있는 입력으로
  최적화기가 '수렴했다'가 아니라 '정답을 냈다'를 확인합니다.
- **불변식 검증.** 단일종목 100% 비중은 그 종목 수익률과 정확히 같아야 하고,
  거래비용이 크면 성과는 반드시 낮아져야 합니다.
- **미래정보 차단 검증.** 마지막 구간 가격을 3배로 조작해도 그 이전 시점의
  워크포워드 비중이 바뀌지 않아야 합니다.
- **화면 검증.** `streamlit.testing.v1.AppTest` 로 위젯과 4개 탭을 헤드리스 렌더링합니다.
- **픽스처.** `tests/fixtures/` 에 FinanceDataReader·yfinance 가 실제로 돌려주는
  모양(yfinance는 2단 컬럼 인덱스)의 CSV를 두고 파싱을 검증합니다.

## 한계

- 공매도·레버리지를 다루지 않습니다. 비중은 항상 0 이상이고 합은 1입니다.
- 세금과 배당을 반영하지 않습니다. 시세는 수정주가 기준입니다.
- 기대수익률로 과거 평균을 씁니다. 평균-분산 최적화는 이 추정치에 민감하며,
  이것이 이 방법론의 가장 큰 실무적 약점입니다.
- 변동성으로 위험을 정의합니다. 상장폐지·유동성 고갈 같은 위험은 잡히지 않습니다.

## 면책

본 소프트웨어는 과거 데이터에 근거한 **참고용 분석 도구**이며 투자 권유가 아닙니다.
과거 수익률이 미래 수익률을 보장하지 않으며, 투자 판단과 그 결과에 대한 책임은
투자자 본인에게 있습니다.
